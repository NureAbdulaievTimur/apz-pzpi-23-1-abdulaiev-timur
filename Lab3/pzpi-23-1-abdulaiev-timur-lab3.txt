Харків – 2026
     1. Мета роботи
     Розробити front-end частину програмної системи у вигляді веб-застосунку для керівного складу. Забезпечити підтримку розділення ролей: інтерфейс для Менеджерів (моніторинг мікроклімату та налаштування локальних правил автоматизації) та інтерфейс для Адміністраторів (управління користувачами, інвентаризація обладнання, обробка системних сповіщень та резервне копіювання). Реалізувати підтримку інтернаціоналізацію (i18n) та адаптивну локалізацію.
     2. Завдання
     Описати прийняті інженерні рішення щодо побудови web-застосунку, описати взаємодію компонентів web-застосунку одне з одним та з серверною частиною. Розробити UML діаграми: прецедентів (Use Case), компонент (Component), пакетів (Package) та діяльності (Activity).
     3. Опис виконаної роботи
     3.1. Текстовий опис інженерних рішень
     Веб-застосунок розроблено за парадигмою SPA (Single Page Application) з використанням бібліотеки React.js. Це забезпечує високу швидкість роботи, оскільки сторінка не перезавантажується при переході між розділами.
     Основні інженерні рішення:
1. Розділення відповідальності за ролями (Role-based UI):
     — ManagerDashboard: Реалізовано як панель управління зонами. Менеджер обирає локацію з випадаючого списку (<select>). Застосунок автоматично знаходить прив'язаний IoT-пристрій, запускає періодичне опитування (Polling) показників датчиків кожні 5 секунд та дозволяє редагувати ClimateRules (мінімальну/максимальну температуру, вологість та допустимий рівень CO₂) для конкретної зони;
     — AdminDashboard: Реалізовано за допомогою вкладеної таб-навігації (Overview, Users, Locations, Devices, Alerts). Це дозволило розвантажити інтерфейс, згрупувавши CRUD-операції (створення локацій, призначення девайсів до кімнат, зміна ролей користувачів, вирішення системних алертів) у відповідних вкладках.
2. Стилізація та UI/UX: Застосовано фреймворк Tailwind CSS. Дизайн побудовано на основі карток (MetricCard, StatCard) з використанням іконок lucide-react для покращення візуального сприйняття.
3. Інтернаціоналізація (i18n) та Локалізація:
     — використано бібліотеку react-i18next. Усі текстові константи винесено у словники (en.json, uk.json). Зміна мови відбувається "на льоту";
     — для локалізації формату дати та часу застосовано вбудований API браузера Intl.DateTimeFormat, який автоматично адаптує вивід (наприклад, 12-годинний чи 24-годинний формат) відповідно до обраної локалі;
     — сортування текстових значень (наприклад, списку користувачів) підтримує локальні правила алфавіту через Intl.Collator, а структура проєкту дозволяє динамічно змінювати атрибут dir="ltr/rtl" для підтримки різних напрямів введення тексту.
4. Резервне копіювання (Backup & Restore): У панелі адміністратора реалізовано механізм експорту даних системи. React збирає дані з API (користувачів, налаштування кліматичних правил) та генерує .json файл, який завантажується на ПК адміністратора (через Blob та HTML5 <a> tag). Імпорт реалізовано через FileReader API, який зчитує JSON-файл для подальшого відновлення конфігурацій.
     3.2. Опис взаємодії компонентів системи
     3.2.1. Внутрішня взаємодія
     Взаємодія базується на хуках useState та useEffect.
     Наприклад, у ManagerDashboard зміна стану selectedLocationId автоматично запускає хук useEffect, який викликає функцію fetchZoneData. Якщо знайдено пристрій, ініціалізується новий таймер setInterval для отримання свіжих даних телеметрії. В AdminDashboard зміна стану activeTab викликає перезавантаження лише тієї частини даних, яка необхідна для поточної вкладки (наприклад, тільки списку пристроїв).
     3.2.2. Зовнішня взаємодія
     Взаємодія з бекендом (ASP.NET Core) здійснюється через HTTP REST API за допомогою бібліотеки Axios.
   — застосунок активно використовує реляційні зв'язки API: щоб отримати клімат кімнати, фронтенд робить запит до /Locations, потім фільтрує /Devices за locationId, і лише потім робить GET /Readings/history/{deviceId};
   — збереження налаштувань клімату (Менеджер) містить розумну логіку: якщо ClimateRules для девайсу вже існують, виконується PUT /ClimateRules/{id}, якщо ні — POST /ClimateRules;
   — обробка алертів (Адміністратор) виконується через спеціалізовані бізнес-ендпоінти (POST /Admin/alerts/{id}/resolve). Після отримання успішної відповіді (HTTP 200), компонент викликає функцію refresh(), яка оновлює React-стан і миттєво прибирає вирішений алерт з таблиці.

Компонент AdminDashboard.jsx (панель адміністратора) є єдиним центром управління системою та побудований за принципом вкладеної таб-навігації (Tab-based UI).
1. Управління станом (State Management): Використовується хук useState для збереження активної вкладки (activeTab) та масивів даних (користувачі, локації, пристрої, сповіщення).
2. Оптимізація мережевих запитів: Хук useEffect має у залежностях змінну [activeTab]. Це означає, що при перемиканні вкладок застосунок не завантажує всю базу даних одночасно, а робить ізольований GET запит через Axios лише для тієї сутності, яка зараз відображається на екрані.
3. Декомпозиція коду: Для дотримання принципу єдиної відповідальності (SRP), вміст кожної вкладки винесено в окремі підкомпоненти (UsersTab, LocationsTab, DevicesTab, AlertsTab).               fetchLocations();
          }, []);
      
          useEffect(() => {
              if (selectedLocationId) fetchZoneData(selectedLocationId);
          }, [selectedLocationId]);
      
          useEffect(() => {
              if (!device) return;
              const interval = setInterval(() => fetchReadings(device.id), 5000);
              return () => clearInterval(interval);
          }, [device]);
      
          const fetchLocations = async () => {
              try {
                  const res = await api.get('/Locations');
                  setLocations(res.data);
                  if (res.data.length > 0) setSelectedLocationId(res.data[0].id);
              } catch (err) { console.error(err); }
          };
      
          const fetchZoneData = async (locId) => {
              try {
                  const devicesRes = await api.get('/Devices');
                  const targetDevice = devicesRes.data.find(d => d.locationId === parseInt(locId));
                  
                  if (targetDevice) {
                      setDevice(targetDevice);
                      fetchReadings(targetDevice.id);
                      fetchRules(targetDevice.id);
                  } else {
                      setDevice(null);
                      setClimateData(null);
                  }
              } catch (err) { console.error(err); }
          };
      
          const fetchReadings = async (deviceId) => {
              try {
                  const res = await api.get(`/Readings/history/${deviceId}`);
                  if (res.data.length > 0) setClimateData(res.data[0]);
              } catch (err) { console.error(err); }
          };
      
          const fetchRules = async (deviceId) => {
              try {
                  const res = await api.get(`/ClimateRules/device/${deviceId}`);
                  setRules(res.data);
                  setRuleForm(res.data);
              } catch (err) {
                  setRules(null);
              }
          };
      
          const handleSaveRules = async () => {
              try {
                  if (rules) {
                      await api.put(`/ClimateRules/${rules.id}`, { ...ruleForm, id: rules.id, deviceId: device.id });
                  } else {
                      await api.post('/ClimateRules', { ...ruleForm, deviceId: device.id });
                  }
                  alert("Settings saved!");
                  fetchRules(device.id);
              } catch (err) { alert(err.response?.data || "Error saving rules"); }
          };
      
          const formatLocalizedDate = (dateString) => {
              if (!dateString) return "";
              return new Intl.DateTimeFormat(i18n.language, {
                  weekday: 'long', year: 'numeric', month: 'long', day: 'numeric',
                  hour: '2-digit', minute: '2-digit', second: '2-digit'
              }).format(new Date(dateString));
          };
      
          return (
              <div className="p-8 max-w-5xl mx-auto animate-fade-in">
                  <header className="mb-10 text-center flex flex-col items-center">
                      <p className="text-secondary font-semibold uppercase tracking-wider text-sm mb-2">{t('dashboard')}</p>
                      
                      <select 
                          className="text-3xl font-extrabold text-primary bg-transparent border-b-2 border-slate-300 focus:border-secondary outline-none py-2 text-center text-center-last"
                          value={selectedLocationId}
                          onChange={(e) => setSelectedLocationId(e.target.value)}
                      >
                          <option value="" disabled>{t('select_zone')}</option>
                          {locations.map(loc => (
                              <option key={loc.id} value={loc.id}>{loc.name}</option>
                          ))}
                      </select>
      
                      <p className="text-slate-400 mt-3 text-sm">
                          {t('last_updated')} {climateData ? formatLocalizedDate(climateData.timestamp) : '-'}
                      </p>
                  </header>
      
                  {!device ? (
                      <div className="text-center text-slate-400 py-20 text-lg">{t('no_device')}</div>
                  ) : !climateData ? (
                      <div className="text-center text-slate-400 py-20 text-lg">{t('awaiting_data')}</div>
                  ) : (
                      <>
                          <div className="grid grid-cols-1 md:grid-cols-3 gap-6 mb-12">
                              <MetricCard title={t('temperature')} value={`${climateData.temperature}°C`} icon={<Thermometer />} color="bg-orange-50 text-orange-600" />
                              <MetricCard title={t('humidity')} value={`${climateData.humidity}%`} icon={<Droplets />} color="bg-blue-50 text-blue-600" />
                              <MetricCard title={t('air_quality')} value={`${climateData.co2Level} ppm`} icon={<Wind />} color={climateData.co2Level > (ruleForm.maxCo2Level||800) ? "bg-red-50 text-red-600" : "bg-emerald-50 text-emerald-600"} />
                          </div>
      
                          <div className="bg-white p-8 rounded-3xl shadow-sm border border-slate-100">
                              <h3 className="text-xl font-bold text-primary mb-6 flex items-center gap-2">
                                  <Settings2 className="text-secondary"/> {t('climate_settings')}
                              </h3>
                              <div className="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-6 mb-8">
                                  <InputField label={t('min_temp')} type="number" value={ruleForm.minTemperature} onChange={e => setRuleForm({...ruleForm, minTemperature: e.target.value})} />
                                  <InputField label={t('max_temp')} type="number" value={ruleForm.maxTemperature} onChange={e => setRuleForm({...ruleForm, maxTemperature: e.target.value})} />
                                  <InputField label={t('min_hum')} type="number" value={ruleForm.minHumidity} onChange={e => setRuleForm({...ruleForm, minHumidity: e.target.value})} />
                                  <InputField label={t('max_hum')} type="number" value={ruleForm.maxHumidity} onChange={e => setRuleForm({...ruleForm, maxHumidity: e.target.value})} />
                                  <InputField label={t('max_co2')} type="number" value={ruleForm.maxCo2Level} onChange={e => setRuleForm({...ruleForm, maxCo2Level: e.target.value})} />
                              </div>
                              <div className="flex justify-end">
                                  <button onClick={handleSaveRules} className="flex items-center gap-2 bg-primary text-white px-8 py-3 rounded-xl hover:bg-slate-800 transition-colors font-medium">
                                      <Save size={18} /> {t('save_settings')}
                                  </button>
                              </div>
                          </div>
                      </>
                  )}
              </div>
          );
      };
      
      const InputField = ({ label, type, value, onChange }) => (
          <div className="flex flex-col">
              <label className="text-sm font-semibold text-slate-500 mb-2">{label}</label>
              <input type={type} value={value} onChange={onChange} className="px-4 py-3 bg-slate-50 border border-slate-200 rounded-xl focus:outline-none focus:ring-2 focus:ring-secondary focus:border-transparent transition-all" />
          </div>
      );
      
      const MetricCard = ({ title, value, icon, color }) => (
          <div className="bg-white p-6 rounded-3xl shadow-sm border border-slate-100 flex flex-col items-center justify-center relative overflow-hidden group">
              <div className={`p-4 rounded-full mb-4 ${color} transition-transform group-hover:scale-110`}>
                  {React.cloneElement(icon, { size: 32 })}
              </div>
              <p className="text-slate-500 font-medium mb-1">{title}</p>
              <p className="text-3xl font-black text-primary">{value}</p>
          </div>
      );
      
      export default ManagerDashboard;
      
Компонент ManagerDashboard сфокусований на моніторингу в реальному часі та налаштуванні правил автоматизації для конкретних офісних зон.
1. Каскадне завантаження даних: Логіка побудована на ланцюжку подій. При виборі кімнати з випадаючого списку змінюється selectedLocationId. Це тригерить useEffect, який шукає IoT-пристрій, прив'язаний до цієї локації. Якщо пристрій знайдено, паралельно виконуються запити на отримання поточної телеметрії (/Readings/history) та існуючих лімітів (/ClimateRules).
2. Моніторинг реального часу (Polling): Реалізовано через setInterval(..., 5000). Кожні 5 секунд React автоматично опитує сервер та оновлює показники на екрані. При зміні пристрою або виході зі сторінки спрацьовує функція очищення (clearInterval), щоб запобігти витоку пам'яті.
3. Розумне збереження налаштувань: Форма редагування кліматичних правил (мін/макс температура, вологість, CO₂) використовує контрольовані компоненти (Controlled Components). При натисканні кнопки "Зберегти" застосунок автоматично визначає тип HTTP-запиту: якщо правила для цього пристрою вже існують — відправляється PUT для оновлення, якщо ні — POST для створення нових.
4. Динамічний UI: Компонент MetricCard містить логіку умовного рендерингу класів Tailwind CSS. Наприклад, якщо рівень CO₂ перевищує встановлений менеджером ліміт, колір картки автоматично змінюється з зеленого на червоний для привернення уваги.
