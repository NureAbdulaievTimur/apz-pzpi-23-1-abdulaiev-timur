Харків – 2026
     1. Мета роботи
     Ознайомитися з процесом розробки клієнтської частини програмної системи для мобільних платформ. Оволодіти навичками проєктування архітектури мобільного застосунку, реалізації інтерфейсу користувача, налаштування мережевої взаємодії з REST API серверної частини та побудови UML-діаграм для документування прийнятих інженерних рішень.
     2. Завдання
     Розробити мобільний програмний застосунок мовою Kotlin для ОС Android. Застосунок повинен бути частиною системи ClimaFlow та взаємодіяти з серверною частиною. Скласти звіт, що містить опис прийнятих інженерних рішень, будову застосунку, опис взаємодії з іншими частинами системи. Розробити UML діаграми: прецедентів (Use Case), компонент (Component), пакетів (Package) та діяльності (Activity).
     3. Опис виконаної роботи
     3.1. Текстовий опис інженерних рішень
     Для розробки мобільного застосунку системи ClimaFlow було обрано платформу Android та сучасну мову програмування Kotlin. Застосунок орієнтований на рядових співробітників офісу (Employee) та виконує роль інформаційного табло з можливістю зворотного зв'язку.
     Основні інженерні рішення:
1. Архітектурний патерн MVVM (Model-View-ViewModel): Використано для чіткого розділення бізнес-логіки (ViewModel), даних (Model) та інтерфейсу користувача (View). Це забезпечує легке тестування та запобігає втраті даних при повороті екрана пристрою.
2. UI Фреймворк Jetpack Compose: Замість застарілого XML-верстання використано сучасний декларативний підхід. Інтерфейс будується за допомогою Kotlin-функцій з використанням компонентів Material Design 3 (картки, кнопки, Snackbar для сповіщень).
3. Мережева взаємодія (Retrofit2 + Gson): Для комунікації з ASP.NET Core REST API використано бібліотеку Retrofit. Вона дозволяє описати HTTP-запити (GET, POST) через інтерфейси Kotlin, а конвертер Gson автоматично перетворює JSON-відповіді у Data-класи (DTO).
4. Асинхронність (Coroutines & Flow): Мережеві запити виконуються у фонових потоках за допомогою корутин (viewModelScope.launch). Для передачі стану на UI використовуються реактивні потоки StateFlow (для даних клімату) та SharedFlow (для одноразових подій, таких як спливаючі повідомлення про успішний відгук).
     3.2. Будова мобільного застосунку
     Структура проєкту розділена на логічні пакети для забезпечення чистоти коду:
   — data.models містить Data-класи (Device, Location, SensorReading, FeedbackDto, MyRoomResponse), які є точним відображенням DTO з серверної частини;
   — data.network — містить інтерфейс ClimaFlowApi з маршрутами до ендпоінтів сервера та об'єкт NetworkClient для ініціалізації Retrofit;
   — ui містить клас MainViewModel, який інкапсулює логіку періодичного опитування сервера (Polling) та відправки відгуків користувачів;
   — MainActivity.kt — точка входу застосунку. Містить Compose-функції (DashboardScreen, MetricCard), які підписуються на uiState з ViewModel і автоматично перемальовують екран при зміні даних.

      class MainViewModel : ViewModel() {
      
          private val _uiState = MutableStateFlow<UiState>(UiState.Loading)
          val uiState: StateFlow<UiState> = _uiState
      
          private val _snackbarMessage = MutableSharedFlow<String>()
          val snackbarMessage: SharedFlow<String> = _snackbarMessage.asSharedFlow()
      
          private var currentDeviceId: Int? = null
      
          init {
              fetchData()
          }
      
          private val CURRENT_USER_ID = 1
      
          private fun fetchData() {
              viewModelScope.launch {
                  while (true) {
                      try {
                          val myRoom = NetworkClient.api.getMyRoom(CURRENT_USER_ID)
                          currentDeviceId = myRoom.deviceId
      
                          val history = NetworkClient.api.getDeviceHistory(myRoom.deviceId)
                          val latestReading = history.firstOrNull()
      
                          if (latestReading != null) {
                              _uiState.value = UiState.Success(
                                  locationName = myRoom.locationName,
                                  reading = latestReading
                              )
                          } else {
                              _uiState.value = UiState.Error("Очікування даних від сенсорів...")
                          }
                      } catch (e: Exception) {
                          println("Помилка: ${e.message}")
                          if (e.message?.contains("404") == true) {
                              _uiState.value = UiState.Error("Вас не призначено до жодної кімнати, або в кімнаті немає сенсора.")
                          }
                      }
                      delay(5000)
                  }
              }
          }
      
          fun sendFeedback(type: String) {
              viewModelScope.launch {
                  try {
                      currentDeviceId?.let { id ->
                          NetworkClient.api.sendFeedback(FeedbackDto(id, type))
                          _snackbarMessage.emit("Дякуємо! Ваш відгук успішно враховано 💙")
                      }
                  } catch (e: Exception) {
                      _snackbarMessage.emit("Помилка з'єднання з сервером 😔")
                  }
              }
          }
      }
      
      sealed class UiState {
          object Loading : UiState()
          data class Success(val locationName: String, val reading: SensorReading) : UiState()
          data class Error(val message: String) : UiState()
      }
     Даний клас (MainViewModel.kt) успадковується від ViewModel і відповідає за бізнес-логіку та управління станом екрану. Логіка побудована на реактивних потоках Kotlin Flow:
1. StateFlow (_uiState) зберігає поточний стан екрану у вигляді sealed-класу (Loading, Success з даними мікроклімату, або Error). Це гарантує, що при перевороті екрана дані не зникнуть.
2. SharedFlow (_snackbarMessage) використовується для обробки одноразових подій, таких як показ спливаючого повідомлення після успішного відправлення відгуку користувачем.
     У блоці init запускається корутина (viewModelScope.launch), що містить нескінченний цикл while(true). Кожні 5 секунд (метод delay) ViewModel асинхронно опитує сервер про стан прив'язаної кімнати та оновлює uiState.

      @OptIn(ExperimentalMaterial3Api::class)
      @Composable
      fun ClimaFlowApp(viewModel: MainViewModel = viewModel()) {
          val uiState by viewModel.uiState.collectAsState()
          val snackbarHostState = remember { SnackbarHostState() }
      
          LaunchedEffect(Unit) {
              viewModel.snackbarMessage.collectLatest { message ->
                  snackbarHostState.showSnackbar(
                      message = message,
                      duration = SnackbarDuration.Short
                  )
              }
          }
      
          Scaffold(
              snackbarHost = { SnackbarHost(hostState = snackbarHostState) },
              topBar = {
                  TopAppBar(
                      title = { Text("ClimaFlow", fontWeight = FontWeight.Bold) },
                      colors = TopAppBarDefaults.topAppBarColors(
                          containerColor = MaterialTheme.colorScheme.primaryContainer,
                          titleContentColor = MaterialTheme.colorScheme.onPrimaryContainer
                      )
                  )
              }
          ) { paddingValues ->
              Box(
                  modifier = Modifier
                      .padding(paddingValues)
                      .fillMaxSize()
                      .background(Color(0xFFF5F7FA))
              ) {
                  when (val state = uiState) {
                      is UiState.Loading -> {
                          CircularProgressIndicator(modifier = Modifier.align(Alignment.Center))
                      }
                      is UiState.Error -> {
                          Text(
                              text = state.message,
                              color = MaterialTheme.colorScheme.error,
                              modifier = Modifier.align(Alignment.Center)
                          )
                      }
                      is UiState.Success -> {
                          DashboardScreen(
                              locationName = state.locationName,
                              temperature = state.reading.temperature,
                              humidity = state.reading.humidity,
                              co2 = state.reading.co2Level,
                              onFeedbackClick = { type -> viewModel.sendFeedback(type) }
                          )
                      }
                  }
              }
          }
      }

Замість традиційної XML-розмітки, інтерфейс описано Kotlin-функціями, позначеними анотацією @Composable (DashboardScreen, MetricCard, FeedbackButton). Рисунок 1.1 — Застосунок
     
     3.3. Взаємодія з іншими частинами системи
     Застосунок працює у режимі "Тонкого клієнта". Мережева взаємодія відбувається за протоколом HTTP.
1. Моніторинг: Раз на 5 секунд застосунок виконує фоновий GET-запит api/Users/{userId}/my-room для визначення локації користувача. Отримавши ID пристрою, виконується запит api/Readings/history/{deviceId} для отримання останніх показників клімату (температура, вологість, CO₂).
2. Зворотній зв'язок (Feedback): При натисканні кнопок "Холодно", "Комфортно", "Спекотно", застосунок генерує DTO-об'єкт та відправляє POST-запит на ендпоінт api/Feedback. Сервер записує ці дані в MS SQL для подальшого аналізу алгоритмами машинного навчання, а застосунок показує спливаюче повідомлення (Snackbar) про успіх.
