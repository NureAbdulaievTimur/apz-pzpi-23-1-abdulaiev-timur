Харків – 2026
     Назва: ClimaFlow.
     Короткий опис системи: ClimaFlow є апаратно-програмною IoT-системою для моніторингу та автоматизованого локального керування мікрокліматом (температура, вологість, рівень CO₂) в офісних просторах та коворкінгах. Система збирає дані з датчиків на робочих місцях, автоматично керує побутовими кліматичними приладами для дотримання санітарних норм та енергоефективності, а також надає адміністраторам детальну аналітику через зручні клієнтські додатки.
3. Scope and Limitations
3.1. Scope of Initial Release
     Початковий реліз системи охоплює повноцінну взаємодію всіх компонентів архітектури: IoT-вузлів, серверної частини (Back-end), Web-клієнта та мобільного додатку. Робота всієї системи виглядає наступним чином:
     1. IoT-частина: Клієнтські апаратні модулі базуються на мікроконтролерах ESP32 з підключенням до корпоративної Wi-Fi мережі. Вони містять цифрові датчики температури та вологості (типу DHT22), а також оптичні NDIR-сенсори для вимірювання реального рівня CO₂. Дані упаковуються в JSON та із заданою періодичністю надсилаються на сервер через HTTP POST запит. Отримавши відповідь від сервера, мікроконтролер керує виконавчими пристроями — розумними реле (Smart Plugs) та ІЧ-трансмітерами для увімкнення/вимкнення локальних кондиціонерів, обігрівачів чи зволожувачів.
     2. Серверна частина (Back-end): Ядро системи реалізовано на платформі ASP.NET Core Web API із застосуванням Clean Architecture. Взаємодія з реляційною базою даних MS SQL Server відбувається через Entity Framework Core. Сервер містить бізнес-логіку (Rule Engine), яка валідує вхідну телеметрію, порівнює її з налаштованими лімітами мікроклімату, зберігає часові ряди показників, генерує сповіщення (Alerts) про критичні відхилення та формує керуючі команди, які повертаються IoT-пристроям у HTTP-відповіді.
     3. Web-клієнт (SPA на React): Single Page Application (SPA) для офіс-менеджерів та HR. Дозволяє створювати віртуальні зони офісу, реєструвати нові IoT-пристрої за їхніми MAC-адресами, гнучко налаштовувати порогові правила автоматизації (ClimateRules), керувати ролями користувачів та переглядати дашборди з графіками історичних показників мікроклімату.
     4. Мобільний клієнт (iOS/Android): Додаток для рядових співробітників, через який вони бачать поточний стан мікроклімату у своїй кімнаті. Головною функцією є можливість залишати фідбек ("Мені спекотно" / "Мені холодно"), що використовується сервером для динамічного коригування кліматичних правил у спільних зонах.
3.2. Scope of Subsequent Releases
     У наступних релізах планується глибока інтеграція алгоритмів Штучного Інтелекту (ШІ) для переходу від жорсткої автоматизації (за фіксованими порогами) до адаптивного предиктивного керування.
     Застосування ШІ:
     — предиктивне клімат-керування, тобто ШІ аналізуватиме прогноз погоди на вулиці та теплову інерцію конкретної будівлі, щоб заздалегідь (до приходу працівників) вмикати опалення чи охолодження, уникаючи пікових навантажень на електромережу;
     — оптимізація комфорту, тобто алгоритми знаходитимуть "ідеальну" цільову температуру на основі аналізу конфліктних голосувань співробітників у мобільному додатку;
     — виявлення аномалій (наприклад, кондиціонер увімкнений, але температура в зоні не падає), що свідчить про поломку техніки або відкрите вікно.
     Для навчання моделей, бекенд безперервно накопичуватиме датасети в MS SQL Server: телеметрію (температура, вологість, CO₂) з часовими мітками; статуси увімкнення кліматичної техніки; дані із зовнішніх API погоди; логи оцінок комфорту від персоналу.
     Оскільки теплофізика кожного офісу унікальна, індивідуальні моделі машинного навчання (наприклад, Random Forest) будуть донавчатися за допомогою хмарних сервісів (враховуючи стек .NET, планується використання Azure Machine Learning). Сервер періодично відправлятиме історичні дані клієнта в Azure для оновлення вагів моделі, а в реальному часі використовуватиме API ШІ для отримання оптимальних параметрів керування реле.
3.3. Limitations and Exclusions
     Як доступне IoT-рішення, комерційна система ClimaFlow має низку свідомих обмежень та функцій, які були навмисно виключені з архітектури:
     — виключено інтеграцію з центральними системами будівлі, а саме система не підключається до загальнобудинкової вентиляції через промислові протоколи. ClimaFlow керує виключно локальними побутовими приладами (через ІЧ-порти та смарт-розетки). Це дозволяє встановлювати систему в орендованих офісах без капітального ремонту інженерних мереж;
     — для спрощення мікрокоду на ESP32 та гарантованої роботи через корпоративні фаєрволи, IoT-пристрої використовують синхронний підхід (HTTP POST раз на хвилину), а не постійне з'єднання. Як наслідок, є технічне обмеження, наприклад, команда ручного увімкнення кондиціонера з Web-клієнта виконається не миттєво, а під час наступного сеансу зв'язку пристрою з сервером;
     — відсутнє візуальне розпізнавання присутності, тобто для збирання даних не використовуються камери чи мікрофони. Це жорстке обмеження введено навмисно для дотримання політики конфіденційності та уникнення спротиву персоналу через страх "стеження" на робочому місці.
